# TermGuard 迭代路线图 —— 译员痛点驱动的深化方向

> 配套 `README.md`（现状）与 `面试讲解与演示指南.md`（当前能力怎么讲）。
> 本文档回答：**如果要"打磨"而非"新开项目"，往哪里深挖、每步做什么、面试怎么讲。**

---

## 〇、战略前提：为什么是"打磨"而不是"新项目"

- 简历已有 3 个项目（RAG / agent-report / TermGuard），数量已超配
- 面试官判断应届生看**单个作品的深度**，不是数量
- 二面大概率 = 深挖 TermGuard + 场景题（"给译员痛点现场出方案"）——现有项目的深化能直接复用为答案
- 结论：把 TermGuard 从"演示工具"升级为"有业务闭环的作品"，边际回报远高于第 4 个项目

## 一、译员工作流 & 真实痛点全景（需求来源）

```
源文件 → 解析格式 → CAT工具翻译(查TM/术语) → 译后QA → LQA打分 → 交付 → 版本更新
```

| # | 译员真实痛点 | TermGuard 现状 | 对应方向 |
|---|---|---|---|
| 1 | 术语跨文件/跨版本打架，术语库更新后旧译文不同步 | ✅ 单文件一致性已做 | 延伸：跨文件 |
| 2 | 只看得到单句，没有上下文（UI截图/前后文）→ 错译 | ⚠️ 无上下文感知 | 方向四 |
| 3 | QA 返工：格式/占位符/长度（译文超 UI 框） | ✅ 部分已做 | 方向五 |
| 4 | 反馈处理完就完了，同样的错下次还犯（无沉淀） | ⚠️ 只有前端"忽略"按钮 | **方向一** |
| 5 | 新项目没有术语库，冷启动全靠人工 | ❌ 未做 | **方向二** |
| 6 | 风格一致性：角色语气、人设、禁词 | ❌ 未做 | 方向五 |
| 7 | 真实数据不是 CSV，是 XLIFF/SRT/JSON 国际化文件 | ❌ 只支持 CSV | 方向三 |
| 8 | 报错看不懂、报告没法给 PM/客户 | ⚠️ 弱 | 方向三/报告导出 |

## 二、方向一：反馈闭环落库 ⭐ 最高优先级

### 解决痛点
4（反馈流失）——直接命中 JD 原文："持续迭代，打磨系统""根据反馈，找到系统优化的关键路径"。

### 现状问题
"忽略/确认"只在前端内存演一下，刷新即丢 → 无法沉淀，规则不会变聪明。

### 功能拆解
1. **裁决落库**：译员对每条问题的操作（确认正确 / 忽略 / 手动纠正）持久化到 `backend/data/reviews.json`
   - 记录：行号、类型、原文/译文、裁决、时间
2. **规则豁免表**：同一类型问题在同一文件被"忽略"≥2 次 → 提示"是否加入豁免规则"（如：该词条在此产品允许变体译法）
3. **术语建议生成**：被"确认"的术语类错误 → 汇总高频词条 → 提示"检测到 N 个高频术语错误，是否一键加入术语库？"
   - 加入时自动带出：源文词条、标准译法（取正确译法）、语境
4. **回归报告**：修复后重跑，展示"较上次改善"（问题数减少、哪些已修复）——闭环可视

### 技术要点
- 后端：reviews 存储模块（沿用 storage.py 的原子写模式）+ 聚合分析接口
- 前端：问题卡片操作升级（确认/忽略 → 调后端），加"闭环"面板
- 数据飞轮叙事：**忽略=教它别误报，确认=教它抓得更准**

### 演示脚本（3 分钟）
> 1. 跑内置 Demo，把 L9（HP→健康点）点"确认"
> 2. 系统弹提示："检测到术语 'HP' 多次误译，建议加入术语库/或展示改善报告"
> 3. 重新质检 → 通过率上升，"较上次修复 1 处问题"
> 4. 讲："译员每次裁决都在训练系统，规则从'通用'变成'懂这个产品'——这就是 JD 说的反馈闭环"

### 面试钩子
> "很多工具做完检查就结束了。我把'译员裁决'变成数据：确认的错沉淀成术语规则，忽略的错沉淀成豁免——系统不是一次性工具，是越用越懂你产品的 QA 搭档。"

## 三、方向二：术语自动提取（Term Extraction）

### 解决痛点
5（冷启动）——新项目没术语库，全靠人工建。JD 加分项"了解术语库 Glossary"的技术化延伸。

### 功能拆解
1. **输入**：纯英文源文（粘贴/文件）
2. **候选提取**（两层）：
   - 统计层：词频 / 相邻词共现（C-value 思路）→ 高频名词短语候选
   - 过滤层：长度、词性（跳过动词/虚词）、是否已存在于术语库
3. **LLM 精筛**：把 Top-N 候选 + 上下文交给大模型，结构化输出"是术语/否 + 建议译法 + 语境"（复用现有 AI 层）
4. **人工确认界面**：候选列表勾选 → 一键入库（可带建议译法）→ 立即可用于一致性检查

### 技术要点
- 复用 llm_check.py 的 OpenAI 兼容调用 + JSON 结构化输出模式
- 统计层无 Key 也能跑（先体验），LLM 精筛可选

### 演示脚本（3 分钟）
> 1. 粘贴一段游戏英文文案（无术语库状态）
> 2. 点"提取术语" → 系统推荐 Cloud Sync / Soulbound / Legionnaire's Blade 等候选，每个带建议译法
> 3. 勾选入库 → 术语库自动 +N
> 4. 直接跑一致性检查 → 故事线完整：**提取 → 建库 → 检查**

### 面试钩子
> "译员的第一个痛点是'新项目没有术语库'。我做的是把'人工翻旧文档找术语'变成'统计+大模型提候选、人来确认'——术语库管理的冷启动自动化。"

## 四、方向三：行业格式接入（XLIFF / SRT / JSON i18n）

### 解决痛点
7（真实文件不是 CSV）+ 8（报告导出）。

### 功能拆解
1. **SRT 字幕解析**（游戏/视频本地化最常用）：
   - 解析时间轴 + 文本 → 双语检查照常跑
   - 字幕特有检查：译文时长估算超限、时间轴重叠、空字幕
2. **XLIFF 解析**（本地化行业标准交换格式）：
   - 读 trans-unit 的 source/target、state（已译/未译）
   - 检查后按 XLIFF 结构回写注释（QA 结论进文件，可直接给 PM/客户）
3. **JSON i18n**：游戏资源常为 `key: 译文` 结构，支持 key 上下文（检查时显示 key 路径作为语境）
4. 前端上传类型扩展 + 解析预览

### 技术要点
- 后端解析器（xml.etree / 自写 SRT 解析），映射为统一 Entry 结构
- 尽量不碰前端解析（后端统一处理）

### 演示脚本（选做）
> 导入一个真实 `.srt` 字幕（预埋 1 条术语 + 1 条超长字幕）→ 报告同时给出术语问题 + "字幕时长估算超出源文 40%" → 讲"我做了译员真正会遇到的格式"

### 面试钩子
> "真实项目第一步是数据打通。CSV 只是演示格式，我补了 SRT/XLIFF——译员从 CAT 工具导出的文件能直接拖进来。"

## 五、方向四：上下文感知检查（升级现有检查）

### 解决痛点
2 + JD 原话"特定语境校验难"。

### 功能拆解
1. **上下文窗口**：检查每条时带上"前 2 句 + 所在章节/文件"（Entry 增加 ctx_before/ctx_after/section 字段）
2. **语境词条增强**：上下文限定词条支持"章节级生效"（如仅在"技能说明"章节内 Cooldown→冷却时间 强制，对话里允许口语）
3. 规则层把窗口内的术语命中计入一致性统计；LLM 层 prompt 携带窗口内容（误译判断更有依据）
4. 前端可开关"使用上下文"（默认开）

### 注意
- 开发量偏大，建议在方向一二之后做；且需想清楚"窗口从哪来"（粘贴时如何提供章节信息 → 可能依赖 XLIFF 的 group 节点，与方向三联动）

---

## 六、方向五：游戏本地化专属小检查（低成本可选项）

### 功能拆解
1. **UI 长度限制检查**：译文长度 > 源文 ×130%（或超配置上限）→ 提醒"可能超出 UI 控件"
2. **禁词/必用词表（Style Guide 雏形）**：术语库扩展字段 `banned`（禁词，出现即报）与 `required`（必用词，缺失即报）——对应游戏分级/品牌规范
3. **语域一致性统计（升级）**：复用 AI 层输出，按文件统计"口语 vs 正式"占比，提示风格漂移

### 定位
- 规则层 30-50 行即可做 1、2；作为面试收尾的"我还考虑了 XX"素材
- 不建议单独作为迭代主线

## 七、推荐执行路径（2-3 周业余时间）

```
第 1 步：方向一 反馈闭环落库      ← 命中 JD 原文，讲"闭环迭代"（必做）
第 2 步：方向二 术语自动提取      ← 讲"懂 Glossary + 冷启动"（必做）
第 3 步：方向三 SRT/XLIFF 导入    ← 讲"懂行业格式"（有时间再做，SRT 优先）
第 4 步：方向四、五               ← 口头延伸或按需小做
```

### 打磨后的面试叙事线（完整故事）
> "我调研了译员工作流 → 发现三个真痛点：术语不一致、新项目冷启动、QA 反馈流失
> → 做了三步闭环：**术语提取建库 → 规则+AI 分层质检 → 译员裁决沉淀回流**
> → 系统越用越懂这个产品的术语规范 —— 这正是 AI 产品助理要解决的'把业务痛点变成工具'。"

## 八、风险与边界（诚实备注）

- 方向三/四依赖"真实格式样本"：演示数据需自己造（仿 SRT/XLIFF 片段即可，不必真拿商业文件）
- 闭环的"规则变聪明"要防止**误豁免**：豁免需留痕（记录谁在何时忽略的），面试被追问时有交代
- 迭代顺序上，方向一、二做完已足够撑起"深化"叙事；三/四/五是加分不是必需——时间不够时果断砍
